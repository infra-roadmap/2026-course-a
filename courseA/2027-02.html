2月：Terraform実践②

コースA：AWS資格（SAA）取得コース

1月に続き、Terraformの実践的な使い方を学びます。「Terraform実践」の後半にあたるこの2月は、前月に比べて分量を抑えめに（1月：2月＝おおむね6：4）、data sourceを使ったCompute構築と、拡張演習・振り返りを行います。並行するSAA-C03の問題演習は、1月の「分野別」中心から、分野をまたいだ「ランダム演習」へ徐々に切り替え、月の後半から最初の模試を投入します（この演習時間もメイン学習時間とは別枠の目安です。data source・Compute構築などTerraform本体の理解が優先のため、時間が足りない場合は模試の開始を3月にずらしても構いません）。

💼 この月で実務的にできるようになること：既存情報を参照するdata sourceの使い方を身につけ、Computeインスタンスまでを一連のコードで構築・拡張できるようになります。

🧭 SAA合格トレーニングシステム ― 1月の「分野ごとの理解確認」に続き、2月は複数分野を横断した設計判断を鍛える段階です。単純なサービス暗記ではなく、要件から適切なAWSサービス・構成を選ぶ力を重視する教材思想を予定しています。

📖 この月で出てくる用語

用語ひとことで言うともう少し詳しく
data source既存の情報を参照する仕組み自分で作ったのではなく、OCI側に既にある情報（可用性ドメイン等）を取得して使う
destroyTerraformで作ったリソースを削除するコマンドコードは残したまま、実際のリソースだけを消せる（terraform destroy）

WEEK 01目安 2h

data source（既存情報の参照）

🎯 このタスクのゴール
自分で作ったのではなく、OCI側に既にある情報（可用性ドメイン等）を取得して使う方法を学ぶ。
📚 使う教材
  • Terraform公式ドキュメント（Data Sources） https://developer.hashicorp.com/terraform/language/data-sources
🛠 具体的な手順
  1. PowerShellを開き、作業用フォルダに cd で移動してから、以降の操作を行う。
  2. data "oci_identity_availability_domains" "ads" {}のようなdata sourceを定義し、可用性ドメインの一覧を取得する。
  3. terraform consoleやterraform planの出力で、取得できた値の中身を確認する。
✅ 成果物
🧭 到達判定
  • data sourceが「自分で作る」リソースと何が違うか説明できる
  • 取得した値をplanやconsoleの出力で確認できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（目安3.5h）
演習 Week 5分野別演習の総仕上げ（弱点分野を優先）
進め方
  • 1月の4週間で間違えた分野・自信が持てなかった分野を優先して、分野別の演習問題を継続する
  • 正解・不正解にかかわらず、選択肢ごとに「なぜ合っているか／なぜ違うか」を解説で確認する流れは1月と同様に続ける
到達目標：1月で扱った全分野について、根拠つきで安定して正解できる状態に近づける。
教材：SAA合格トレーニングシステム
WEEK 02目安 2.5h

Compute構築（data sourceを使って構築）

🎯 このタスクのゴール
取得した可用性ドメインの情報を使って、Computeインスタンスをコードで構築する。
📚 使う教材
  • Terraform公式ドキュメント（Data Sources） https://developer.hashicorp.com/terraform/language/data-sources
🛠 具体的な手順
  1. PowerShellを開き、作業用フォルダに cd で移動してから、以降の操作を行う。
  2. 取得した値を使ってoci_core_instanceリソースを記述する（subnet_idには12月WEEK03でTerraform管理下に構築したPublic Subnetを指定し、10月の手動Subnetは対象にしない）。Shapeは9月week3で手動作成していたインスタンス（10月着手前にすでに削除済み）と同じVM.Standard.A1.Flexにするが、次週WEEK03で2台目を追加してもAlways Free枠（合計2 OCPU・12GB）に収まるよう、1台目は1 OCPU・6GBに変更する。9月分のComputeはすでに削除済みで、10月の手動Compute（E2.1.Micro）ともシェイプ・枠が別のため、Ampere A1のAlways Free枠は今回のTerraform applyのためにそのまま使える。
  3. terraform fmtとterraform validateでコードを整形・検証してから、terraform applyでVCN〜Compute（コンピュート）までを一連の実行で構築できることを確認する。
✅ 成果物
🧭 到達判定
  • data sourceで取得した値をComputeの構築に利用できる
  • 手動作成分を先に削除してからapplyする必要がある理由を説明できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（目安3.5h）
演習 Week 6ランダム演習への切り替え
進め方
  • 分野別演習から、分野をまたいだランダム問題演習に比重を移す
  • 「どの分野が来るか分からない」本番に近い状態に慣れることを意識する
  • 間違えた問題は分野別演習のときと同様、解説を読み込んでから次に進む
到達目標：分野を意識せず出題される問題に対しても、落ち着いて分野を見極めて解答できるようにする。
教材：SAA合格トレーニングシステム
WEEK 03目安 2h

Terraformコード拡張演習

🎯 このタスクのゴール
variableを使って2台目のインスタンスを追加する小演習を行い、変更差分の考え方を手に馴染ませる。
📚 使う教材
  • これまでのTerraformコード一式 https://github.com/
🛠 具体的な手順
  1. 拡張演習：week2で構築したCompute（コンピュート）環境に、variableを使って2台目のインスタンスを追加する（display_nameは1台目と別名にする）。2台目もVM.Standard.A1.Flex（1 OCPU・6GB）とし、1台目（1 OCPU・6GB）と合わせてAmpere A1のAlways Free枠（合計2 OCPU・12GB）に収める。terraform planで追加分の差分だけが出ることを確認してからapplyする。
  2. 動作確認ができたら、Always Free枠を使い切らないよう2台目はterraform destroyで削除しておく（variable定義自体はコードに残してOK）。
✅ 成果物
🧭 到達判定
  • variableを使って構成を拡張したときの、差分の考え方を説明できる
  • 確認後にdestroyでリソースを片付ける理由を説明できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（目安4h）
演習 Week 7模試①実施
進め方
  • 本番と同じ制限時間で模試を1回解く
  • 採点し、分野別（IAM／ネットワーク／ストレージ／DB／コンピューティング等）の正答率を記録する
  • 間違えた問題は解説を読み込み、選択肢ごとの正誤の理由を確認する
到達目標：ここまでの演習の成果を、本番形式の模試で一度測ってみる。
教材：SAA合格トレーニングシステム
