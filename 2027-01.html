1月：Terraform実践①

コースA：AWS資格（SAA）取得コース

コードでの構築に慣れてきたところで、Terraformの実践的な使い方を学びます。当初1ヶ月分だった「Terraform実践」の内容を1月・2月の2ヶ月に分け、前半にあたるこの1月に比重を置いて（1月：2月＝おおむね6：4）じっくり進めます。この月はplan/applyの読み方とstate管理を扱います。また、12月で座学ロードマップが一区切りついたことを受けて、この1月から並行タスクが「座学（インプット）」から「問題演習（アウトプット）」に切り替わります。1日20〜30分程度、分野別の演習問題を解きながら解説を読み込む形で進めます（この時間もメイン学習時間とは別枠の目安です。演習には後述の「SAA合格トレーニングシステム（開発予定）」を使用する予定です）。1月・2月の本体はTerraform実践（plan/apply・state管理）です。SAA演習によってTerraform実践の時間が圧迫される場合は、SAA演習量を減らすか、後述する2月の模試開始時期を後ろ倒ししてください。

💼 この月で実務的にできるようになること：terraform planの差分表示（+/-記号）の読み方と、applyでの実行・検証の流れを体に馴染ませたうえで、tfstateの中身とstate系コマンドの使い方を理解できるようになります。

🧭 SAA合格トレーニングシステム（開発予定）

本ロードマップと連動した、SAA合格のためのオリジナル学習システムを構築予定です。現時点ではまだ開発予定・構築中で、すでに完成した問題バンクとして提供されているものではありません。単に問題を解いて終わりにするのではなく、「問題作成→内容・解説の検証→問題演習→解説による理解確認→弱点分析→弱点に応じた類題・補強問題→再演習」というサイクルを回しながら、AWSサービスの知識と、要件から適切な設計を選択する力を段階的に鍛えることを目指す仕組みです。開発はGPTとの対話・相談を活用しながら進める予定です（学習者自身がGPTを使う必要はありません）。

問題作成→ 内容・解説の検証→ 問題演習→ 解説で理解確認→ 弱点分析→ 類題・補強問題→ 再演習

1月はこのシステムの最初の段階として、分野別に「なぜ合っているか／なぜ違うか」を確認しながら理解を固めるフェーズに位置付けています。目的は本試験問題の再現ではなく、AWSサービスの役割の理解、似たサービスの比較、要件から適切な設計を選ぶ力を鍛えることです。

📖 この月で出てくる用語

用語ひとことで言うともう少し詳しく
plan / apply変更内容の予告 / 実際の適用plan＝「これから何を作る/変えるか」の確認、apply＝実際に実行
差分表示（+/-）planの結果に表示される追加・削除・変更の記号「+」は新規作成、「-」は削除、「~」は変更を意味する
state（ステート）Terraformが管理する「現在の状態」の記録実際に作られたリソースの情報がtfstateファイルに記録される。壊すと復旧が大変なので取り扱い注意

WEEK 01目安 2.5h

terraform planの理解（差分表示の読み方）

🎯 このタスクのゴール
plan（予告）の差分表示（+/-記号）の読み方を、実際に手を動かして理解する。
📚 使う教材
  • Terraform公式CLIドキュメント https://developer.hashicorp.com/terraform/cli
🛠 具体的な手順
  1. PowerShellを開き、作業用フォルダに cd で移動してから、以降の操作を行う。
  2. terraform planを実行し、差分表示（+/-記号）の読み方を復習する。
  3. コードを意図的に1行変更し（例：インスタンス名を変える）、再度planで差分が正しく検出されることを確認する。
  4. terraform validateも合わせて実行し、文法エラーがないことを確認する習慣をつける。
✅ 成果物
🧭 到達判定
  • plan結果に表示される+/-記号がそれぞれ何を意味するか説明できる
  • コードを変更したとき、planで正しく差分を検出できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（1日20〜30分目安）
演習 Week 1IAM・セキュリティ分野の演習
進め方（1日20〜30分 × 週5〜6日ペース、合計目安2.5h）
  • 9月・12月の座学（AWS基礎、IAM・セキュリティ、セキュリティ設計の深化）の範囲を中心に、分野別の演習問題を解く
  • 正解・不正解にかかわらず、選択肢ひとつひとつについて「なぜ合っているか／なぜ違うか」を解説で確認する
  • 理解があいまいな用語が出たら、その場で座学ロードマップの該当回に戻って復習する
到達目標：「なんとなく正解した」をなくし、選択肢ごとの正誤の根拠を自分の言葉で説明できる状態にする。
教材：SAA合格トレーニングシステム
WEEK 02目安 3h

terraform applyの理解（実行と検証）

🎯 このタスクのゴール
planで確認した変更を実際に適用し、意図した内容がOCI側に反映されることを検証する。
📚 使う教材
  • Terraform公式CLIドキュメント https://developer.hashicorp.com/terraform/cli
🛠 具体的な手順
  1. PowerShellを開き、作業用フォルダに cd で移動してから、以降の操作を行う。
  2. 前週コードを1行変更した状態のまま、terraform planで差分を再確認する。
  3. terraform applyを実行し、yesと入力して変更を適用する。
  4. OCIコンソール（またはCLI）で、変更した内容（インスタンス名など）が実際に反映されていることを確認する。
⚠️ つまずきやすいポイント
  • applyはいきなり実行せず、必ず直前にplanで内容を確認してから実行する癖をつける。
✅ 成果物
🧭 到達判定
  • applyの前に必ずplanで内容を確認する理由を説明できる
  • 適用した変更が実際にOCI側へ反映されていることを確認できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（1日20〜30分目安）
演習 Week 2ネットワーク・高可用性分野の演習
進め方（1日20〜30分 × 週5〜6日ペース、合計目安2.5h）
  • 座学のVPC・ネットワーク①②、高可用性・DR、ネットワーク設計の深化の範囲を中心に、分野別の演習問題を解く
  • 正解・不正解にかかわらず、選択肢ひとつひとつについて「なぜ合っているか／なぜ違うか」を解説で確認する
  • 理解があいまいな用語が出たら、その場で座学ロードマップの該当回に戻って復習する
到達目標：Public/Private Subnet、NAT Gateway、Multi-AZ、RTO/RPOなど、ネットワークと可用性に関する典型的な選択問題を根拠つきで解けるようにする。
教材：SAA合格トレーニングシステム
WEEK 03目安 3h

state管理①（tfstateの構造理解）

🎯 このタスクのゴール
Terraformが「今何を管理しているか」の記録がどのように保存されているかを知る。
📚 使う教材
  • Terraform公式ドキュメント（State） https://developer.hashicorp.com/terraform/language/state
🛠 具体的な手順
  1. PowerShellを開き、作業用フォルダに cd で移動してから、以降の操作を行う。
  2. terraform.tfstateの中身をエディタで開いて構造（JSON形式）を確認する。
  3. terraform state listで管理対象のリソース一覧を表示する。
⚠️ つまずきやすいポイント
  • tfstateには接続情報などの機密が平文で入ることがあるため、Gitには絶対に含めない（12月にすでに.gitignoreへ追加済みのはず）。
✅ 成果物
🧭 到達判定
  • tfstateがJSON形式でどのような情報を保持しているか説明できる
  • tfstateをGit管理してはいけない理由を説明できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（1日20〜30分目安）
演習 Week 3コンピューティング・ストレージ・DB分野の演習
進め方（1日20〜30分 × 週5〜6日ペース、合計目安2.5h）
  • 座学のコンピューティング、ストレージ、RDS・Aurora、DynamoDB・ElastiCacheの範囲を中心に、分野別の演習問題を解く
  • 正解・不正解にかかわらず、選択肢ひとつひとつについて「なぜ合っているか／なぜ違うか」を解説で確認する
  • 理解があいまいな用語が出たら、その場で座学ロードマップの該当回に戻って復習する
到達目標：EC2/Lambda/Elastic Beanstalk、S3/EBS/EFS、RDS/Aurora/DynamoDB/ElastiCacheの使い分けを、要件文から選択できるようにする。
教材：SAA合格トレーニングシステム
WEEK 04目安 2.5h

state管理②（詳細確認とCLI突き合わせ）

🎯 このタスクのゴール
個々のリソースの詳細を確認し、Terraformの記録と実際にOCI上に作られているリソースが一致していることを検証する。
📚 使う教材
  • Terraform公式ドキュメント（State） https://developer.hashicorp.com/terraform/language/state
🛠 具体的な手順
  1. PowerShellを開き、作業用フォルダに cd で移動してから、以降の操作を行う。
  2. terraform state show <resource>で特定リソースの詳細を確認する。
  3. OCI CLIとも突き合わせる。 oci compute instance list --compartment-id <コンパートメントOCID>を実行し、terraform state listの内容と実際に作成されているリソースが一致していることを確認する。
✅ 成果物
🧭 到達判定
  • terraform stateの記録と実際のOCIリソースが一致していることを、CLIと突き合わせて確認できる
📝 並行タスク：SAA-C03 問題演習ロードマップ（1日20〜30分目安）
演習 Week 4アプリケーション統合・コスト最適化・運用分野の演習
進め方（1日20〜30分 × 週5〜6日ペース、合計目安2.5h）

  • 正解・不正解にかかわらず、選択肢ひとつひとつについて「なぜ合っているか／なぜ違うか」を解説で確認する
  • 理解があいまいな用語が出たら、その場で座学ロードマップの該当回に戻って復習する
到達目標：SQS/SNS/EventBridge、コスト最適化の選択肢、CloudWatch/CloudTrail/Configなど、1月に扱った以外の残りの分野を一通り演習でカバーする。
